# 更新視窗互動測試

`UpdateSimulator` 使用正式的 `UpdateWindow`，搭配本機模擬下載函式。
更新提示、下載進度與失敗狀態都在同一個原生視窗內切換。
不需要連接 AirPods，不會存取更新 API、下載檔案、啟動安裝程式或修改正式設定。
發行頁與手動下載操作會被攔截，只在控制面板顯示結果。

## 建置與啟動

先依 `Docs/Build.md` 配置 Qt 5.15.2 Win32 環境，並啟用 `APD_BUILD_TESTS=ON`。
在專案根目錄執行：

```powershell
cmake --build Build --config RelWithDebInfo --target UpdateSimulator
.\Build\Binary\UpdateSimulator.exe
```

此目標需明確指定才會建置，不加入 CTest，也不包含在安裝包中。
可與正式 AirPodsDesktop 同時執行；關閉控制面板即可結束測試工具。

## 親自操作

1. 在控制面板按「開啟更新視窗」。
2. 在更新提示按「立即更新」，確認原視窗保留，更新內容的位置不變。
3. 觀察取得下載大小與慢速進度：64 MiB，約每秒增加 1%，到 95% 後等待選擇。
4. 回到控制面板按「模擬失敗」。
5. 確認卡片顯示紅色失敗提示，焦點移到「關閉」；點「手動下載」只會顯示攔截結果，視窗保持開啟。
6. 關閉失敗視窗，確認控制面板仍在，再按「開啟更新視窗」重測。

也可在下載中按「模擬成功」，觀察 100% 與準備安裝狀態後關閉視窗；
不會啟動真正的安裝程式。

## 設計狀態檢查

- 開啟視窗前，可選「正式版本」「預覽版本」或「無更新說明」。空內容應改成文字列，不留空白文字框。
- 外觀與語言下拉選單可即時切換深色／淺色／隨系統，以及繁體中文／英文。
- 下載中可選「等待下載大小」，持續觀察忙碌進度條與已下載容量。
- 選「停留在 100%／準備安裝」，確認手動下載停用、卡片外提示消失、視窗高度縮短。
- 在上述狀態按「模擬失敗」或「模擬成功」，觀察後續結果。100% 本身不代表安裝程式已啟動。
- 下載與準備安裝時，Esc／標題列關閉應無效。失敗後兩者都可關閉，測試工具仍繼續執行。
- 用 Tab／Shift+Tab 切換焦點，確認按鈕不改變尺寸且文字完整。
- 狀態列優先保留完整進度數值。英文或較長的狀態文字可能顯示省略號，停留滑鼠可查看全文。

可用獨立的程序環境測試 DPI（測完移除環境變數）：

```powershell
$env:QT_FONT_DPI = '96' # 固定 Qt 基準 DPI，避免與目前螢幕縮放相乘
$env:QT_SCALE_FACTOR = '1.5' # 也測試 1、2
.\Build\Binary\UpdateSimulator.exe
Remove-Item Env:QT_SCALE_FACTOR
Remove-Item Env:QT_FONT_DPI
```

`UiRenderingTests` 自動驗證同一視窗與列位置、操作結果、下載關閉限制及主題／語言更新，
並將正式版、預覽版、空內容、長內容、等待大小、下載中、準備安裝、失敗等狀態截圖寫入
`Build/UiValidation/update-*.png`。截圖包含語言、主題與 `QT_SCALE_FACTOR`，不提交產物。

本工具為了讓控制面板可操作，以非模態方式顯示正式視窗；
正式主程式仍使用模態流程。這是介面互動測試，不驗證真實網路或安裝程序。
